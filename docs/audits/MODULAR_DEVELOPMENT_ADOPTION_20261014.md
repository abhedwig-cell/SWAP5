## Accepted-state closure decision

The isolated executable proof reduces the real accessor's provider closure from
154 to **20**, while copying the actual base/temporal type declarations and six
clone/readiness/history procedures literally from the pinned production backend.
Only the accessor's hypothetical provider import changes in the isolated tree.
Both O0/O2 build, link and sample accepted heat; foreign lineage is rejected.
Compile times are 1.445497 s O0 and 3.628480 s O2 in this one feasibility sequence.
These timings are not a matched full architecture benchmark or production speed claim.

**Decision: feasible interface/type separation; production move deferred pending
shared HY/RT/restart successor authority.** No production type or layout changes.
The base owns allocatable snow, temperature, macropore, salt and Rutter continuations;
its clone deep-copies them. Temporal history is private and cloned through its
snapshot/replace methods. Thus a heat-only wrapper or duplicated state type would
lose accepted identity or continuation semantics. Identical fields in a new module
are a different Fortran type. Both the backend and every type consumer must use
one new canonical type identity before a split can enter production.

The actionable successor is: move declarations and exact bound implementations
into one state-provider module, expose the existing backend public names by
re-export, retain all factories/parameter/layout guards and every serialized restart
field/order, and migrate consumers atomically. Do not introduce a second physical
state or accept a caller-supplied temperature. Reconcile central RT/HY/F-KT with
restart/coupling and snow/heat/macropore/solute/Rutter owners. Required evidence:
all variant deep-clones and temporal-history identity, accepted/candidate nonmutation,
trial/accept/retry/rollback, restart variants, real Richards heat/root/drainage,
joint crop weather and coupling, the exact highest frost owner successor and full
applicable preservation. Existing backend exact-blob guards require explicit
successor admission, not editing expected hashes to declare success. Prototype
results cannot be inherited as those gates. Production split cost remains UNKNOWN.
