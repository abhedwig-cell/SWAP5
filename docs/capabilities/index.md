# Status-A capability review pages

These pages turn admitted Status-A capability records into a reviewer-facing narrative without replacing the underlying scientific, qualification or canonical-admission authorities.

Use them when you need to understand **what the capability currently means**, **which boundary is actually admitted**, **how it interacts with SWAP5 state ownership**, and **what it explicitly does not claim**.

## Authority discipline

These pages are explanatory. For a current admission decision, use this order:

1. [Status-A current status](../status-a/CURRENT_STATUS.md);
2. [Status-A theory, code and evidence traceability](../status-a/TRACEABILITY.md);
3. the capability-specific qualification/admission records;
4. the explanatory page in this section.

A capability page must never silently broaden its authority. If a scientific detail cannot be reconstructed from accepted theory/code/evidence, the correct documentation action is to record the missing authority or evidence rather than manufacture a definitive statement.
