Status: preregistered implementation contract. No admission follows from this file.

The existing adapter has now consumed actual accepted Richards endpoints at its
unchanged 1e-6 cm certificate budget and 1e-12 cm mass gate. An application-owned
call is still required: a passing test of an unused component is not production
integration.

Add one opt-in `run_interception_window_interval` entrypoint to the existing
production application owner. The caller retains the existing P0 companion
owners; no duplicate physical or interception storage is introduced. This slice
is the explicit uniform Hupsel net-rain/fixed-flux, root-inactive, mode-2 profile.
Automatic file-weather/calendar, crop/root extraction and dynamic surface regime
switching remain outside this entrypoint's qualification. F-APP04 demand and
precipitation bindings remain their independently tested production contracts.

Before physical execution, validate every companion column identity and current
accepted time and prepare only local copies of its proposed progress. Execute
the admitted production standalone application with the supplied effective
forcing. Publish the companion copies only after every physical result is
complete, committed, mass-complete and accepted by the adapter. On any rejection,
restore all application committed carriers from deep copies, discard results and
publish zero interception amounts. This opt-in call is atomic across its columns;
existing standalone partial-progress semantics remain unchanged. Groundwater
contexts and file-weather orchestration cannot use this entrypoint.

No solver, error norm, accuracy budget, physical formula or P0 implementation is
changed. The refined qualification uses the already documented numerical limits
(24 retries, 4096 substeps, minimum solver dt1e-12 day) and preserves the previous
8-retry negative result. It establishes possibility at that explicit accuracy,
not an application default or efficiency claim.

Qualification requires real application initialization, a rejected preflight and
unchanged physical/cursor state, four unequal accepted endpoints, exact-once
canopy/soil mass, companion continuation, stale companion rejection after a real
commit, and O0/O2 identity. Keep the original component/F-APP03/F-APP04/P0 drivers
unchanged and execute them. Prove that removing the new import, entrypoint and
procedure recovers the entire incumbent bootstrap body. Broader weather/crop/
dynamic-top scientific admission and whole historical capability closure are not
inferred from this restricted application entrypoint.

committed soil snapshots before execution. An unsupported regime, invalid crop
input or inconsistent source aggregate returns no physical/source mutation.
