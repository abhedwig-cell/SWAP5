## 5. D2 fault operator

The D2 fault semantics are unchanged:

> a rejected physical throughflow is prematurely added to an accepted external ledger before retry/re-execution, after which the valid accepted transfer is added normally.

For reversed flow, accounting magnitudes must respect physical direction.

At the rejected long trial:

- top flux `q < 0` is accepted-ledger inflow if wrongly published;
- bottom flux `q < 0` is accepted-ledger outflow if wrongly published.

Therefore the qualification-only rejected contribution is prospectively defined as:

- faulty accepted inflow increment = `abs(q) * rejected_dt = 1.0e-8 cm`;
- faulty accepted outflow increment = `abs(q) * rejected_dt = 1.0e-8 cm`.

This sign-aware expression is frozen before execution and is the same semantic operator as D2: publish rejected throughflow as accepted accounting.
