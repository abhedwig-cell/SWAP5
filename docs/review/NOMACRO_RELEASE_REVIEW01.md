## User route findings

1. **Preparation depends on an excluded model run.** Public `--prepare-archive` accepts the Andelst selector only. `daily_host.prepare_reference` builds the original distribution, copies the Andelst case and runs the unmodified macropore reference, checking return100 and swap.ok. A no-macro user cannot follow this route without that extra computation. No such run was launched in this review.
2. **Research provider is the practical qualification prerequisite.** The no-macro workflow extracts `research/hybrid-water01/hybrid-hupsel-linux-20261111.tar.xz` and reuses original source/object providers. This proves a qualified provider route, but not a clean supported source build on the user's machine. Binary portability and ABI/OS/compiler requirements need explicit boundaries.
3. **SaltFarm first-use ordering is incomplete.** `require_no_macro_input` reads the prepared case before `build` can copy a missing registered case. The original-workbook SaltFarm materialization must therefore be explicitly staged before release preflight. The workflow does this; the current getting-started route does not.
4. **Entry documentation is stale.** Getting-started still limits hybrid Grassgrowth to four days and primarily describes separate native routes. README disclaims a broad interface. A broad interface is unnecessary, but the three-profile supported release route must be explicit, including exact Python/compiler prerequisites, source archive identity/acquisition, start commands and output meaning.
5. **Heat export is qualified but accessed through research assembly.** The normal launcher has no supported-heat export option; full-period accounting uses `qualify_original_heat_accounting.py` with provider, native bundle and control-root arguments. Either expose/repackage that existing observer through the supported route or explicitly describe heat export as an optional research facility. Do not imply normal run output includes the qualified heat receipts.
6. **Scope/error clarity.** CLI help still describes hybrid reference preparation as Andelst-only and offers native and macro models beside the release profiles. Restrict the supported documented route to registered hybrid no-macro models; retain other existing routes separately. No broad CLI redesign is needed.

No prebuilt end-user distribution was independently located or validated. This is an unverified availability category, not proof that none exists anywhere.

## Scientific disposition and risk

**Grassgrowth:** original-block unrounded water agrees with the retained original print to about6.822e-13cm over eight quantities. This does not transfer to the distinct native thermal route. Its day188 uptake excess0.011301596216cm and full-period oxygen discrepancy0.010648529111cm remain failed science. Existing water-only controls support time-grid sensitivity; their remaining0.000226656cm oxygen discrepancy remains unresolved. Same-state oxygen-kernel agreement argues against a uniquely demonstrated oxygen implementation defect in those tested states. Rounded crop/oxygen output limits comparison. Release consequence: preserve the failures and exclude a claim of qualified oxygen-sensitive prediction; do not require a new general reference campaign for the named original-block execution release.

**Hupsel:** corrected hybrid versus separate high-output reference has maximum soil-water difference0.009324942287cm, GWL0.244556026095cm, daily uptake0.001113283189cm, oxygen0.000242093550cm and solute stock0.012516223035mg/cm2. Runoff/pond, CDE endpoint and harvest-interception defects have explicit repairs; remaining downstream differences are not all causally attributed. The frozen day584 oxygen criterion still FAILS. Reference refinement changes exceed its bound by46.1x and9.17x in the two existing families, so the reference itself is insufficiently resolved. A favorable alternative day584 output cannot replace the oracle. Release consequence: acceptable only for the restricted execution/compatibility use above with prominent limits; insufficient for a general oxygen, salinity or crop-accuracy guarantee. Application-specific prediction claims require their own accuracy assessment.

**Heat:** full selected numerical conduction/storage bookkeeping is functionally qualified. Missing mass-carried boundary energy is a physical information/coverage limitation. Setting it to zero is a retained failed counterfactual. This blocks complete energy-balance use and caller thermal coupling claims, but not a release explicitly limited to the supported accounting.

**SaltFarm:** original-workbook materialization provenance is explicit; R-preprocessor byte equivalence and whole scientific equivalence are not qualified. It is an additional functional salinity/irrigation test, not an independent universal accuracy certificate.

No tolerance is changed. Balance closure, restart identity and compiler agreement cannot establish scientific accuracy alone. The restrictions are part of the product boundary, not a footnote converting failed criteria to PASS.
