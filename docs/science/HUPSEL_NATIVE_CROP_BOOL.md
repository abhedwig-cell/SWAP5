# Private native crop scalar logical validation

The preregistered native decoder experiment reproduces malformed allocation-presence acceptance. A genuine mature S5HR0004 file, with only its crop biomass allocation token changed to 2, -1 or 256 and its outer CRC resealed, reaches the nonadvancing post-read boundary in all three cases. The valid control does too. This is decoder evidence, not numerical restart or production admission from a foreign executable.

The copied-source candidate validates the host compiler's exact native true/false byte representations before interpreting each of 32 explicit scalar logical serialization sites. It refuses other representations on both read and write. Canonical stream bytes, schema, public signatures and physical algorithms remain unchanged. No hardcoded true-is-one rule is introduced.

Actual coherent 236-provider Windows O0/O2 builds pass two-day original initialization, exact own day1-to-day2 restart, six existing public writer atomic refusals, eleven app refusals and twelve resealed scalar-token refusals per optimization. Unmodified same-optimization two-day controls have byte-identical checkpoints and crop/budget outputs. The exact helper separately passes native true/false byte roundtrip, eight invalid read/write cases and truncated read controls at O0/O2. Failed helper reads leave the destination unchanged; failed helper writes emit no bytes.

This is deliberately a **private scalar candidate**. Opaque derived records still include logical state, including `evolution_continuation%anthesis_reached`; that state is not covered by the scalar helper. The public writer controls above exercise existing nonfinite-pressure failures, not malformed internal logical publication. Full nested owner controls, opaque-record treatment and explicit source-bound production successor admission remain required before production adoption. No production source, schema, existing admission gate, oxygen criterion or reference authority changes in this unit.
