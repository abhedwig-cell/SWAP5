# F-VQ12 — F-KT05 / F-SI05 source-bound admission

## Purpose

F-VQ12 independently admits the qualified downstream contracts produced by F-KT05 and F-SI05 without merging their development branches and without manufacturing a joint production postimage.

The qualification scope is:

`DOWNSTREAM_SOURCE_BOUND_FKT05_FSI05_ADMISSION_WITH_CONTRACTUAL_NONCONFLICT_ONLY`

## Positive admission candidates

1. F-KT05: reusable opaque committed checkpoint carrier and same-committed-state replay on the canonical kernel transaction entrypoint.
2. F-SI05: committed production HeadCalc workspace seam on the focused main Newton/Jacobian/tridiagonal route and forced band-fallback route.
3. Contractual non-conflict between these independently qualified lines: F-SI05 does not change transaction semantics, generic time semantics or the shared F-KT type; F-KT05 explicitly records the exact qualified F-SI05 boundary and keeps checkpoint ownership in F-KT.
4. Both source lineages descend from the F-CI18 canonical closeout.
5. F-VQ11 remains the exact qualification ancestor for F-VQ12.

## What this does not qualify

F-VQ12 does **not** claim that F-KT05 and F-SI05 have been executed together in one production source tree. There is no joint executable postimage in this unit. Contractual non-conflict is therefore weaker than composed-runtime qualification.

It also does not qualify:

- full reference Richards reentrancy;
- parallel real HeadCalc execution with 1/2/4/8 workers;
- full unrounded SWAP water-balance identity;
- production B1.10 reference execution;
- production MultiSWAP runtime admission;
- macropore, implicit-conductivity, minimum-timestep or all bottom-boundary workspace paths;
- MODFLOW coupling.

## Mass conservation

Mass conservation remains absolute. F-KT05 preserves the existing unrounded trial-mass gate and does not introduce checkpoint mass accounting. F-SI05 qualifies a focused unrounded equation-residual identity only. That focused identity must never be promoted into a claim about the complete SWAP accounting chain.

## Transaction and ownership boundary

The reusable checkpoint is F-KT-owned. It can capture the physical committed state plus lineage/revision/time provenance but cannot publish or restore committed state by itself and contains no solver scratch or warm-start data.

The F-SI05 workspace owns Newton/Jacobian/tridiagonal and band-solver scratch per worker or active solve job. F-SI does not gain commit or rollback authority.

## Persist-first status

The admission scope and fail-closed matrix are persisted before F-VQ12 replay qualification. C01–C05 can be promoted only after the exact F-VQ12 gate and immutable downstream replays are green. C06–C11 remain blocked regardless of those focused replays.
